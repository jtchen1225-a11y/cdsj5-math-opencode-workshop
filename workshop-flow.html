120 分鐘｜講師現場執行版 V3

小學數學 AI Agent 工作坊 逐分鐘講師操作導航

講師使用原則：這不是「照讀稿」。每一段只抓四件事：投影甚麼、老師何時操作、你要觀察甚麼、出錯時怎樣不拖慢全班。正式課堂不處理環境安裝。

🟢 A 組操作 (1–20號老師) 🔵 B 組操作 (21–40號老師) 🟡 全體觀看 (看講師投影) 🔴 暫停操作 (全班切紅燈停手)

⏱️ 120 分鐘總覽時間表（11 階段）

總計嚴格等於 120 分鐘
時間 (min) 核心階段 主要內容與教師行動 完成標準與里程碑
0–10 min 先看成果 開場 2 分鐘直觀展示 ➔ 完成版 Demo（教案、工作紙、答案版）➔ 宣佈今天的四件事 知道今天不是學 Prompt，而是建立工作流
10–18 min 認識工作區 打開 Starter Pack Math-Agent-Workshop ➔ 第一次讓 OpenCode 檢查專案 正確開啟根目錄，AI 回報資料夾結構
18–33 min 實作一：備課 TASK 1 備課：讀取示範教材 PDF ➔ 產出 40 分鐘教案 ➔ AI 自我專業檢查 產出 01_課堂備課草案.md
33–43 min 停下講規則 🔴 暫停操作 講授 AGENTS.md 作為「AI 助教長期守則」 ➔ 開新對話測試規則 理解「普通聊天每次重貼 vs 專案長期遵守」
43–62 min 實作二：分層 TASK 2 同一核心目標下的分層 ➔ 產出 A/B/C 三層練習與教師答案版 ➔ 分層質檢 ➔ 現場只改 C3 產出 02_學生工作紙 ＋ 03_教師答案
62–68 min 中段整理 第 60 分鐘合格線檢查：確認 output 內累積 01、02、03 三大文件；缺者助教個別補救 全班不等待，確認基礎成果齊備
68–87 min 實作三：同步修改 試教回饋三項要求 ➔ TASK 3A 先分析變更影響清單 ➔ TASK 3B 跨檔案同步修訂並檢查一致性 產出 04_同步修改紀錄.md
87–105 min 實作四：重用 換入新教材 P5-小數乘法.pdf ➔ TASK 4A 說出流程 ➔ TASK 4B 完整重用成熟架構 產出 output/reuse/ 三份新成果
105–113 min 成果封裝 執行 Word 輸出指令 ➔ 輸出教案、學生版、答案版 3 份 Word ➔ 教師只驗三件事 形成明天可直接列印交付的真實文件
113–118 min 工作流提升 回看今天用了甚麼 ➔ 拆解 OpenCode、AGENTS.md、Skill、Workflow 分工 理解專案規則與技能，為第二場鋪路
118–120 min Exit Ticket 回答 3 個問題 ➔ 寫入 MY-NEXT-TASK.md ➔ 宣佈第二場帶真實教材入場 帶走真實問題與教材，圓滿結課！

📋 11 階段逐分鐘講師四象限卡片

0:00–0:10 min 階段 1｜先看成果：如果一份教材 PDF，可以變成這些東西？

節奏劃分：0:00–0:02 開場（不介紹技術） ➔ 0:02–0:06 完成版 Demo ➔ 0:06–0:10 今天的四件事。

🖥️ 投影甚麼
只放一句：「如果一份教材 PDF，可以變成這些東西呢？」並展示：示範教材 PDF ➔ 40 分鐘教案 ➔ 三層工作紙 ➔ 答案版 ➔ 同步修改 ➔ 換教材重用。快速切換展示三份成果。
🗣️ 講師要說
「今天不先教技術名詞。先看兩分鐘，看看這件事值不值得你學。」指出傳統聊天最容易出現「工作紙改了、答案沒改、教案忘了改」；今天要處理的是文件之間的連鎖關係。
👥 老師操作 🟡 全體觀看
前 6 分鐘老師只觀看投影。0:06–0:10 時，在學習單首頁寫下自己平時備課最花時間的一項工作（可留空到最後再填）。
🎯 預期成效
建立「今天是做真實數學教師工作，不是學軟件按鈕」的期待；聚焦 Workflow，而不是零散的 Prompt 清單。
0:10–0:18 min 階段 2｜認識工作區：打開 Starter Pack 專案資料夾

節奏劃分：0:10–0:15 打開專案 ➔ 0:15–0:18 第一次讓 OpenCode 看專案（A組 0:16 Enter，B組 0:17 Enter）。

🖥️ 投影甚麼
檔案總管中顯示 Math-Agent-Workshop，展示 AGENTS.md、materials、output、templates 四大核心要素。
🗣️ 講師要說
「不是打開單一 PDF，而是把整個工作資料夾交給 OpenCode。AGENTS.md 等一下再揭曉。」引導大家依組別錯峰送出檢查指令。
👥 老師操作 🟢 A組 0:16 🔵 B組 0:17
用 OpenCode 開啟 Math-Agent-Workshop 專案資料夾。貼入專案檢查 Prompt，按組別錯峰 Enter，要求 AI 說明看到的目錄與教材。
🎯 預期成效
所有人看到同一專案根目錄；OpenCode 回報主要資料夾、教材與專案用途，建立受控操作的安全感。
0:18–0:33 min 階段 3｜實作一：第一次備課（TASK 1：分析先於生成）

節奏劃分：0:20 貼 Prompt ➔ 0:22 A 組 Enter ➔ 0:23 B 組 Enter ➔ 0:26 看成果 ➔ 0:29 自我檢查。

🖥️ 投影甚麼
AI 正在執行：讀教材 ➔ 理解內容 ➔ 形成教學判斷 ➔ 建立文件。提醒：我們指定了輸出位置 output/01_課堂備課草案.md，不只是在聊天框拿一段答案。
🗣️ 講師要說
「AI 可以快速整理與起草，但教材依據是否充分、難度是否適切、教學取捨是否合理，仍然由我們數學老師把關！」
👥 老師操作 🟢 A組 0:22 🔵 B組 0:23
執行 TASK 1 Prompt。生成後打開 output/01_課堂備課草案.md，只看：①學習目標 ②常見錯誤 ③Exit Ticket。執行教師反思 Prompt。
🎯 預期成效
每位老師成功在 output 目錄保存第一份備課草案；體會「先分析教材、後設計教案」的 Agent 流程。
0:33–0:43 min 階段 4｜停下操作｜現在才講 AGENTS.md（概念轉折）

重要提醒：先切紅燈 🔴 暫停操作，全體停手！這是本場第一個重大認知躍遷。

🖥️ 投影甚麼
對比投影：普通聊天（每次手動輸入「請你記得…」） vs Agent 專案（AGENTS.md 永遠遵守）。展示培訓版 AGENTS.md 長期工作守則。
🗣️ 講師要說
講師只講三點：① 重複要求放進規則，不必每次重貼；② 規則服務教師工作，不取代教師判斷；③ 涉及學生個資時，先去識別化。
👥 老師操作 🔴 暫停 ➔ 測試
先停止輸入聽講師講解。隨後開啟新對話，輸入測試 Prompt：「這個專案要求你進行學生分層時，最重要的三項規則是甚麼？」
🎯 預期成效
AI 準確回答核心目標一致、支架不同、A/B/C 定位等分層規則。學員親眼見證規則在不同對話中依然有效。
0:43–1:02 min 階段 5｜實作二：同一核心目標下的分層（TASK 2：真假分層）

節奏劃分：0:48 A 組 Enter ➔ 0:49 B 組 Enter ➔ 左右分屏驗收 ➔ 分層質檢 ➔ 現場只改 C3。

🖥️ 投影甚麼
等待期間投影「真假分層對比表」：假分層＝只把數字變大；真分層＝核心概念相同、支架不同、認知要求不同、解釋深度不同。
🗣️ 講師要說
「同一班有人做完很快，也有人連第一步都不知道怎樣開始。分層是真實教學問題。如果 C 層只是數字變大，立即介入調整認知維度！」
👥 老師操作 🟢 A組 0:48 🔵 B組 0:49
執行 TASK 2 Prompt。左右分屏打開 02_三層學生工作紙.md 與 03_教師答案及錯因.md。核對題號一致性，執行只改 C3 精修指令。
🎯 預期成效
產出學生版與答案版雙份文件；體會五大認知要求（表徵、解釋、比較策略、錯誤診斷、情境應用）的真正分層。
1:02–1:08 min 階段 6｜中段整理：第 60 分鐘成果里程碑檢查

全班齊步走：1:05–1:08 所有老師只確認 output 內已有 01、02、03 三個文件。缺文件者舉手，由助教個別補救；全班不等待。

🖥️ 投影甚麼
展示 output 目錄結構：① 01_課堂備課草案.md ② 02_三層學生工作紙.md ③ 03_教師答案及錯因.md。
🗣️ 講師要說
「現在開始，我們不是在生成新東西，而是在管理已有的教學成果！下半場的所有修改與重用，都建立在這三份成果之上。」
👥 老師操作 🟡 全員核查
檢查 output 資料夾。如有缺失立刻舉手由助教協助從 backup 導入；進度正常者微休息或預覽文件排版。
🎯 預期成效
全體 40 位老師 100% 達成上半場基準合格線，確保下半場無縫推進。
1:08–1:27 min 階段 7｜實作三：一次要求，多份文件同步修改（TASK 3）

節奏劃分：試教回饋 ➔ TASK 3A 影響清單 ➔ TASK 3B 跨檔同步（A組 1:18 Enter，B組 1:19 Enter）。

🖥️ 投影甚麼
對比投影：錯誤做法（有一點要改就全部重生成） vs Agent 做法（提出變更 ➔ 分析影響 ➔ 修改受影響位置 ➔ 一致性檢查）。
🗣️ 講師要說
「核心詞是『同步』。重點不是 AI 幫我改了，而是 AI 知道改動一個地方會牽動教案、工作紙與答案哪些細節！」
👥 老師操作 🟢 A組 1:18 🔵 B組 1:19
先執行 TASK 3A 取得變更影響清單；確認無誤後執行 TASK 3B 同步修改。核對 02、03、04 三份文件中的第 3 題、第 6 題與新 reasoning 題。
🎯 預期成效
產出 output/04_同步修改紀錄.md；學會掌控跨檔案連動修改，告別「改了工作紙忘了改答案」的歷史痛點。
1:27–1:45 min 階段 8｜實作四：換教材，不換工作方法（TASK 4：資產重用）

節奏劃分：換入新教材 P5-小數乘法.pdf ➔ TASK 4A 說出流程 ➔ TASK 4B 完整重用（A組 1:34 Enter，B組 1:35 Enter）。

🖥️ 投影甚麼
比較 output/ 與 output/reuse/ 兩個目錄：變的是數學內容；不變的是流程、分層理念、文件架構與檢查要求。
🗣️ 講師要說
「第四個 Aha Moment！教材會換、班級會換、單元會換；但好的工作方法不需要每次重新發明。Prompt 可以複製，Workflow 可以重用！」
👥 老師操作 🟢 A組 1:34 🔵 B組 1:35
執行 TASK 4A 檢驗 Agent 記憶；隨後執行 TASK 4B，產出 output/reuse/ 資料夾下的三份新成果。檢查是否杜絕了上一課分數內容的誤搬。
🎯 預期成效
體驗到專案資產的長期價值，學會如何將一套成熟工作流複製到小學數學科所有教學單元。
1:45–1:53 min 階段 9｜成果封裝：最後才輸出 Word 可交付文件

容錯原則：今天的成果不是聊天紀錄，是可以明天拿進課堂的文件。若 Word 故障，不在最後十分鐘大修環境，保留 Markdown 即算圓滿完成。

🖥️ 投影甚麼
展示 output/final/ 內的 Word 檔案：分數加減法_教師教案.docx、學生工作紙.docx、教師答案版.docx。
🗣️ 講師要說
「草稿用 Markdown 管理，乾淨純粹；最後交付才轉 Word。老師只驗三件事：Word 能打開、學生版沒答案、題號完全一致。」
👥 老師操作 🟡 全員執行
執行 Word 輸出 Prompt。在 output/final/ 打開 Word 檢查排版與 A4 列印適應性。
🎯 預期成效
獲得排版規範、結構清晰的正式 Word 教學材料，滿足教務與課堂印刷要求。
1:53–1:58 min 階段 10｜工作流提升：回看今天用了甚麼

概念總結：第一次介紹 Skill。下一場才把一次性工作坊升級成持續工作流。

🖥️ 投影甚麼
架構圖：OpenCode ＋ AGENTS.md ＋ 文件工具 ＋ 資料夾結構。指出我們沒有引入複雜資料庫或 API，安全可控。
🗣️ 講師要說
「AGENTS.md 是專案長期要遵守的規則；Skill 是遇到特定工作時的執行技能。第二場我們將建立個人專屬 AI 教師工作台！」
👥 老師操作 🟡 聆聽思考
對照自己的專案架構，理解長期守則、單元教材與生成檔案的職責分離。
🎯 預期成效
建立工程級 AI 備課思維框架，為進階校本自動化流程奠定認知基礎。
1:58–2:00 min 階段 11｜Exit Ticket：把真實問題帶進第二場

收尾金句：「下一場，我們不再用我的教材；開始用你自己的真實工作！」

🖥️ 投影甚麼
Exit Ticket 三個問題，以及第二場自帶材料清單：正在教的教材 PDF、平時工作紙、學校教案模板、最花時間的教學工作。
🗣️ 講師要說
「今天我們帶著滿載成果的資料夾離開，同時留下一張通往下一場的門票。請認真寫下你自己的真實教學痛點。」
👥 老師操作 🟡 完成存檔
執行 Exit Ticket Prompt，將三項回答保存在專案根目錄下的 MY-NEXT-TASK.md。收拾專案檔案，離場。
🎯 預期成效
完成離場憑證存檔；從「學員」心態轉變為「帶著真實業務問題來共備」的成熟專案主導者！

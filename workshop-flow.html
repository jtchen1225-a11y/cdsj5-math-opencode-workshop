⏱️ 120 分鐘講師逐分鐘教案
七維度現場精準 Run Sheet

照時間碼往下走，嚴格遵守「真教材 → 真問題 → 真產出 → 真使用」主線。只有標示「全班 ENTER」的節點才要求所有學員同時送出，確保全班節奏同步、不脫節、不慌亂。

📖 欄位讀法指引： 投影＝講師投影畫面（P01~P12） ｜ OpenCode＝輸入內容 ｜ ENTER＝真正送出時間 ｜ 預期＝巡視查驗證據 ｜ 故障備案＝不拖全班的最短處理。

⏱️ 第 1 個 10 分鐘區段
000:00–009:59（第 0–10 分鐘）

破冰宣導、四字主線、建立心智框架、明確 120 分鐘成功標準，全班同步開啟專案資料夾。

時間碼 投影 🗣️ 講師做／說 ⌨️ 輸入內容 ENTER 節點 👥 學員動作 🎯 預期畫面／故障備案
000:00 P01 ↗ 站在投影旁，不先開 OpenCode。說：『今日不是工具安裝課。』 — — 電腦開好 OpenCode Desktop，但先不要操作。 預期：全班注意力在講師。 備案：若仍有人登入：安排鄰座共用，不停全班。
001:00 P01 ↗ 交代唯一前設：Desktop 已可用、模型已連接、Preflight 已課前完成。 — — 確認手上有 Starter Pack + 真教材。 預期：學員知道課堂不處理安裝。 備案：Preflight 未完成者先跟組員共用。
002:00 P02 ↗ 投影四字主線。逐字講：真教材、真問題、真產出、真使用。 — — 跟著看四字主線。 預期：建立全課心智框架。 備案：不要展開技術細節。
003:00 P02 ↗ 問：『一句 Prompt 能不能出工作紙？能。但它知道我們的教材嗎？』 — — 口頭回應／點頭。 預期：學員開始理解 Context 問題。 備案：若氣氛冷：直接舉一個『五年級分數』例。
004:00 P03 ↗ 投影成功標準：今天每人至少完成一次完整 Agent 循環。 — — 看成功標準。 預期：知道不是比誰生成得多。 備案：提醒：完整三層文件屬加分，不是必要。
005:00 P03 ↗ 說明 120 分鐘節奏：前半先理解，後半才產出與修訂。 — — 不操作。 預期：學員不急著輸入。 備案：若有人已開始問 AI：請暫停。
006:00 P03 ↗ 強調教師角色：『AI 做草稿，教師做判斷。』 — — 記住三問審核會在後面使用。 預期：形成教師主導定位。 備案：—
007:00 P03 ↗ 說明課堂同步規則：『我說 Enter 才全班一起送出。』 — — 把游標停在輸入框，不送出。 預期：全班理解同步節奏。 備案：有人先送出：叫他停止後等待。
008:00 P03 ↗ 說明故障規則：單機故障不拖全班；兩人共用也算完成。 — — 與鄰座確認可互助。 預期：降低技術焦慮。 備案：—
009:00 P04 ↗ 轉入專案地圖：『現在才打開專案。』 開啟 01-Agent-Project — 跟著打開同一資料夾。 預期：全班進入同一專案。 備案：找不到資料夾：用 README-START-HERE 定位。

013:00 Live：AGENTS.md 重點講：AGENTS.md 是長期規則，不是一次 Prompt。 — — 只閱讀，不輸入。 預期：理解『Project rules』概念。 備案：—

015:00 Live：AGENTS.md 指第 4 節證據標記：三個狀態。先只認名字。 — — 圈／記三個標記。 預期：知道稍後用來審 Agent。 備案：—
016:00 Live：AGENTS.md 指第 5 節順序：READ→DIAGNOSE→QUESTION→… — — 沿流程看一次。 預期：知道不能直接跳到生成。 備案：—

018:00 P05 ↗ 投影一句：『AGENTS.md = 這個 Agent 長期工作的校規。』 — — 把 AGENTS.md 留著。 預期：形成記憶點。 備案：—

020:00–029:59（第 20–30 分鐘）

時間碼 投影 🗣️ 講師做／說 ⌨️ 輸入內容 ENTER 節點 👥 學員動作 🎯 預期畫面／故障備案
020:00 P06 ↗ 說：『今天不用假教材；用未來 1–2 週真的會教的。』 — — 把第一份真教材複製到 materials。 預期：materials 內出現真實檔案。 備案：沒帶教材：與同科同級共用。
021:00 P06 ↗ 提醒不放學生姓名、成績、個資。 — — 快速檢查教材是否含個資。 預期：私隱風險被控制。 備案：有個資：改用去識別版本。
022:00 P06 ↗ 建議清楚檔名：01-課本、02-現有練習、03-教師資料。 — — 必要時重新命名。 預期：Agent 較容易辨認材料。 備案：—
023:00 P06 ↗ 請另備第二份教材，最後 Reuse 用。 — — 把第二份放入 materials 或桌面備用。 預期：Reuse 有材料。 備案：沒有第二份：最後與鄰座交換。
024:00 P07 ↗ 投影 RDQ。說：『第一個 Prompt 最大要求：不要生成。』 — — 回到 OpenCode 輸入框。 預期：準備同步送出。 備案：—
025:00 Live：OpenCode 貼上 Prompt A；講師逐行指給大家看，不按 Enter。 貼上 Prompt A 等待 全班貼上 Prompt A，不送出。 預期：輸入框已完整貼好。 備案：貼錯：用 prompt-cards/01 找回。
026:00 Live：OpenCode 再次提醒：先列檔名；最多 5 問；提問後停。 Prompt A 保留 等待 檢查自己最後一句是『不要生成學習單』。 預期：輸入內容一致。 備案：—
027:00 Live：OpenCode 倒數 3、2、1。 Prompt A 🔥 全班 ENTER 同時按 Enter。 預期：Agent 開始讀專案與材料。 備案：若跳權限：只批准讀檔所需操作。
028:00 Live：OpenCode 不要解說，讓大家看 Agent 先做甚麼。 — — 觀察第一批輸出。 預期：應先見到讀檔／分析，而非 worksheet。 備案：若直接生成：立即用 Prompt R。
029:00 Live：OpenCode 說：『先找它有沒有列實際檔名。』 — — 核對檔名與自己的材料。 預期：至少看到 1–3 個真實檔名。 備案：漏讀：要求『先補讀 X，再繼續』。

030:00–039:59（第 30–40 分鐘）

031:00 Live：OpenCode 第二個檢查：有沒有先分析學習內容／核心概念。 — — 標記一項『它理解得對』。 預期：開始形成教材診斷。 備案：若太泛：叫它引用具體教材內容。
032:00 P08 + Live ↗ 投影三種證據標記，同時保留 OpenCode 視窗。 — — 找輸出中三種標記。 預期：看到 MATERIAL-SUPPORTED 等。 備案：未使用標記：稍後 Prompt B 強制重整。
033:00 P08 ↗ 解釋 MATERIAL-SUPPORTED：教材真的寫／呈現了甚麼。 — — 在自己輸出找一例。 預期：能分辨 evidence。 備案：—
034:00 P08 ↗ 解釋 INFERRED：合理，但不是教材原句／明示。 — — 找一例推測。 預期：開始審 AI。 備案：—
035:00 P08 ↗ 解釋 NEEDS-TEACHER-CONFIRMATION：AI 不應替老師猜。 — — 找一項要自己回答的資訊。 預期：教師角色回到中心。 備案：—
036:00 Live：OpenCode 如果輸出已完成，請全班把游標回輸入框。 — — 準備 Prompt B。 預期：同一節奏重新同步。 備案：慢機先繼續，其他人等待。
037:00 Live：OpenCode 貼 Prompt B，不按 Enter。 貼上 Prompt B 等待 全班貼好。 預期：輸入框有證據重整 Prompt。 備案：—
038:00 Live：OpenCode 說：『這一步不是挑 AI 錯字，而是挑證據邊界。』 Prompt B 等待 理解目的。 預期：— 備案：—
039:00 Live：OpenCode 倒數 3、2、1。 Prompt B 🔥 全班 ENTER 同時按 Enter。 預期：Agent 重新分類判斷。 備案：模型慢：讓學員先讀上一版。
⏱️ 第 5 個 10 分鐘區段
040:00–049:59（第 40–50 分鐘）

040:00 Live：OpenCode 巡場看 Prompt B 結果。 — — 比較前後分析。 預期：推測與證據被分開。 備案：若仍混淆：點名一項要求它說明證據。
041:00 Live：OpenCode 要求每人找一項自己要糾正的地方。 — — 在紙／筆記記下 1 個修正。 預期：每位教師準備一次專業介入。 備案：找不到：從難點、課時、學生差異挑一項。

043:00 Live：OpenCode Agent 應只保留最多 5 個澄清問題。 — — 讀最後的問題。 預期：問題聚焦設計條件。 備案：若 >5：輸入『只保留最重要 5 個』。
044:00 P07 ↗ 講一分鐘：這就是 Context Engineering，不是 Prompt 花式寫法。 — — 停止操作聽講。 預期：理解 Agent 主動問教師。 備案：—

046:00 Live：OpenCode 提醒：不要為了填滿而虛構學生情況。 Prompt C 等待 只填自己真正知道的。 預期：真實性保持。 備案：—
047:00 Live：OpenCode 給 60 秒完成填寫。 Prompt C 等待 完成用途、時間、差異等。 預期：輸入框已準備。 備案：—

049:00 Live：OpenCode 檢查 Agent 是否停下。 — — 核對條件摘要是否正確。 預期：完成 Context freeze。 備案：若有錯：立即更正 1 句後再繼續。

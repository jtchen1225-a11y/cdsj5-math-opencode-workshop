13 大最短處置守則 ＋ Preflight 檢驗

課堂時間每分每秒都至關重要。現場最高原則：個別機器故障 → 兩人共用；全班節奏優先！遇到狀況不重開對話、不花 10 分鐘修環境，嚴格按最短 SOP 處置。

🚨 現場第一鐵律： 任何 Agent 跑偏，第一選擇不是重開對話，而是使用 Prompt R（停止生成，重新閱讀 AGENTS.md，回到當前 Phase）。
🚨 快速查看 Prompt R 救援指令 ⏱️ 查看 120 分鐘逐分鐘流程

A ｜ 課前必須完成檢驗（不計入 120 分鐘）

正式 120 分鐘內不處理環境安裝；所有學員應在課前完成以下 Preflight 檢查。

✓
OpenCode Desktop 已安裝：能正常開啟，課堂指定模型已連接且連線正常。
✓
教材已下載解壓：學員已下載並解壓 v2.3 OpenXML Starter Pack 於本機。
✓
真實教材準備就緒：每位學員準備至少一份未來 1–2 週真正會使用的教材，最好另備第二份備用。
✓
執行 00-Preflight.md：在 OpenCode 執行 requirements/00-Preflight.md，必須看到 DOCX_PREFLIGHT_READY。
✓
PDF 狀態說明：PDF 最好亦 READY；若 PDF 未 READY 但 DOCX READY，照常上課，課後再處理 PDF。
✓
禁忌警報：不要在正式 120 分鐘內處理 Office 安裝、CLI、Node、uv 或 Git。

B ｜ 13 大典型現場故障最短處置矩陣

現場精準對照，按標準處置，保住全班進度與教師心理舒適度。

⚠️ 故障 01 ｜ Agent 一開始直接生成工作紙 高頻處置 SOP
⚡ 現場最短處理： 立即貼 Prompt R；說『回到 READ/DIAGNOSE，不要生成』。
⚖️ 講師原則： 不重開對話、不責怪學員。
⚠️ 故障 02 ｜ Agent 沒列出實際讀取檔名 高頻處置 SOP
⚡ 現場最短處理： 要求：『先列出你實際成功讀取的檔名；漏讀 X 請先補讀。』
⚖️ 講師原則： 確認 Context 真正進入。
⚠️ 故障 03 ｜ PDF 讀不到／解析失敗 高頻處置 SOP
⚡ 現場最短處理： 換同課另一份可讀 PDF/Word；或兩人共用真教材。
⚖️ 講師原則： 不花 10 分鐘修單一檔。
⚠️ 故障 04 ｜ Agent 把推測當事實 高頻處置 SOP
⚡ 現場最短處理： 使用 Prompt B；要求三類證據標記。
⚖️ 講師原則： 把問題轉為 evidence lesson。
⚠️ 故障 05 ｜ Agent 問超過 5 個問題 高頻處置 SOP
⚡ 現場最短處理： 輸入：『只保留真正會改變設計的最多 5 個問題。』
⚖️ 講師原則： 避免問卷化。
⚠️ 故障 06 ｜ 生成速度太慢 高頻處置 SOP
⚡ 現場最短處理： 第一版只做核心練習＋應用＋Exit Ticket；分層只做同 2 題三層。
⚖️ 講師原則： 保住完整 Agent 循環。
⚠️ 故障 07 ｜ OpenCode 跳 shell 權限 高頻處置 SOP
⚡ 現場最短處理： 只選 Allow once／允許本次。
⚖️ 講師原則： 不要開全域自動允許。
⚠️ 故障 08 ｜ DOCX READY、PDF NOT READY 高頻處置 SOP
⚡ 現場最短處理： 照常繼續；以 DOCX 作正式產物，課後再處理 PDF。
⚖️ 講師原則： v2.3 本來就分開兩條管線。
⚠️ 故障 09 ｜ DOCX NOT READY 高頻處置 SOP
⚡ 現場最短處理： 與鄰座共用另一台已通過 Preflight 的電腦。
⚖️ 講師原則： 正式課不修環境。
⚠️ 故障 10 ｜ Agent 修訂時整份重寫 高頻處置 SOP
⚡ 現場最短處理： 要求：『回復未指定部分，只保留本次指定修改。』
⚖️ 講師原則： 強化 maintenance 概念。
⚠️ 故障 11 ｜ A 版變成低年級題 高頻處置 SOP
⚡ 現場最短處理： 要求恢復相同核心目標，只增加 scaffold。
⚖️ 講師原則： 分層不是降級。
⚠️ 故障 12 ｜ C 版只有加題量 高頻處置 SOP
⚡ 現場最短處理： 要求增加解釋、比較、策略、推理；不增加超綱知識。
⚖️ 講師原則： 分層看認知深度。
⚠️ 故障 13 ｜ Reuse 仍殘留上一課 高頻處置 SOP
⚡ 現場最短處理： 輸入：『清除上一課具體知識內容，重新讀第二教材後再診斷。』
⚖️ 講師原則： 規則可重用，內容必須重建。

C ｜ 第一堂最低完成證據（8 大驗收清單）

每位老師在 120 分鐘結束時必備的學習成果證據，檢驗真實教學落地。

☑
materials 中有真實教材：Agent 能明確列出實際成功讀取的檔名，絕非虛構。
☑
完成完整 RDQ 流程：完成 READ → DIAGNOSE → QUESTION，且任課教師至少介入糾正／補充 Agent 一次。
☑
第一版內容經三問審核：切實回答「對教材嗎？對學生嗎？明天敢用嗎？」並完成局部修訂。
☑
實體 DOCX 匯出：output/02-worksheet/ 內至少產生一份真正大於 0 位元組的 DOCX；PDF 有則更好。
☑
分層示範完成：產出 A/B/C 差異表 ＋ 同一組 2 題三層示範文件（output/03-differentiated/）。
☑
同步修訂落地：完成一次「只改指定部分」的同步修訂，並重新輸出至 output/04-revised/。
☑
第二教材 Reuse 成功：指定第二份真實教材，重新完成 READ → DIAGNOSE → QUESTION，驗證工作流重用。
☑
Exit Ticket 反思：選定一份未來 1–2 週真正會印出進課堂使用的產物，完成課後實踐約定。

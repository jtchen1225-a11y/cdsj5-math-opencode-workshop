🛠️ 疑難排解與 30–40 人現場 SOP

收錄 10 大初學者高頻操作問題，以及 30–40 人校園 Wi-Fi 現場故障分級處置方案。
遇到任何錯誤先停手，不要狂按 Enter。按照「現象 → 原因 → 動作 → 驗證」快速排除！

💡 課堂處置第一原則：
「遇到錯誤：不要重複狂按 Enter。先停、看錯誤碼，按備援流程處理。任何單一電腦問題立即交技術助手，主講教學節奏不停。」

🧭 10 大初學者高頻問題速查（SKILL.md 規範）

每項問題均提供單一明確的修正動作與驗證步驟：

🔍 放大黑板
問題 1

OpenCode 開啟了錯誤的資料夾

① 現象 Symptom

輸入指令後，Agent 回報找不到 AGENTS.md 或 materials/，工作區看到無關檔案。

② 可能原因 Likely cause

在使用者根目錄、下載資料夾或 ZIP 壓縮檔內直接啟動了 OpenCode，未切換至專案根目錄。

③ 修正動作 Action

關閉當前視窗，確認 Starter Pack 已解壓至桌面，重新雙擊 01_啟動OpenCode培訓.bat。

④ 驗證步驟 Verify

在 OpenCode 中輸入 Prompt 1，確認 Agent 正確列出 materials/ 與 AGENTS.md。

🔍 放大黑板
問題 2

PDF 不在 materials/ 或無法可靠讀取

① 現象 Symptom

Agent 提示「找不到示範教材」或停止報告「PDF 包含不可解析之掃描圖層」。

② 可能原因 Likely cause

教材 PDF 被移動、名稱拼寫不符，或系統缺乏外部 PDF 提取外掛。

③ 修正動作 Action

依照 AGENTS.md 備援規則：改為指定讀取 backup/P5-分數加減法-示範教材.txt 文字版備用教材。

④ 驗證步驟 Verify

Agent 回應能正確讀取文字檔內容，並註明來源為備用文字教材，不再停滯。

🔍 放大黑板
問題 3

Agent 在確認需求前就擅自開始生成教材

① 現象 Symptom

剛發送教材分析 Prompt，Agent 卻直接輸出了一整份包含 10 題的題目與考卷。

② 可能原因 Likely cause

模型發散或漏讀了 AGENTS.md 中「未確認需求前不得動工」的底線限制。

③ 修正動作 Action

立即發送指令糾偏：「請嚴格遵守 AGENTS.md。停止生成成品，先向我提出 6 個需求確認問題。」

④ 驗證步驟 Verify

Agent 停止輸出試卷，轉為條列 6 個關鍵問題等待教師回答。

🔍 放大黑板
問題 4

Agent 回報找不到 AGENTS.md

① 現象 Symptom

執行 Prompt 1 時，Agent 回答「本專案目錄下未發現 AGENTS.md 檔案」。

② 可能原因 Likely cause

工作區根目錄未正確包含 AGENTS.md，或檔案被誤移入子目錄。

③ 修正動作 Action

確認專案最外層有 AGENTS.md。若遺失，從 resources/sample-agents.md 複製一份置於根目錄。

④ 驗證步驟 Verify

重新發送 Prompt 1，確認 Agent 能準確列出學校專屬規則。

🔍 放大黑板
問題 5

產出檔案被寫到 output/ 以外的目錄

① 現象 Symptom

新生成的 Markdown 或 HTML 散落在專案根目錄或 materials/ 內。

② 可能原因 Likely cause

指令中未強調存放路徑，或 Agent 忽略了路徑規範。

③ 修正動作 Action

輸入糾正指令：「根據專案規則，將剛才生成的檔案移動或重新儲存到對應的 output/ 子目錄下。」

④ 驗證步驟 Verify

檢查 output/01-first-version/ 等資料夾，確認檔案已就位且根目錄保持乾淨。

🔍 放大黑板
問題 6（高危險）

老師或 Agent 誤圖覆蓋 materials/ 原始教材

① 現象 Symptom

提示訊息詢問是否允許覆蓋 materials/ 內的 PDF 或既有檔案。

② 可能原因 Likely cause

輸入修改要求時，誤將儲存目標指定到了來源資料夾。

③ 修正動作 Action

選擇拒絕（No）。重新下達指令，明確指示儲存於 output/03-revised/。

④ 驗證步驟 Verify

查看 materials/ 檔案修改時間，確認原始 PDF 毫髮無損。

🔍 放大黑板
問題 7

生成內容過於空泛、脫離校本需求

① 現象 Symptom

題目出現初中代數、或是未定義分母過大的無效重複題。

② 可能原因 Likely cause

在 Prompt 3 需求訪談時給出的約束過少（只說「隨便出幾題」）。

③ 修正動作 Action

編輯 requirements/task-spec.md，精確寫入年級、分母限制（≤20）、題數（8題）與作答時間。

④ 驗證步驟 Verify

讓 Agent 重新對齊規格書，產出題目精準落在教學目標內。

🔍 放大黑板
問題 8

分層作業只改了標籤，題目實質沒有分層

① 現象 Symptom

A/B/C 三個版本的題目幾乎一樣，僅是數字微調或換個題目編號。

② 可能原因 Likely cause

未明確指定支援版需要「圖形/步驟支架」，挑戰版需要「推理與比較」。

③ 修正動作 Action

使用 Prompt 5 的嚴格要求，或調用 worksheet-generator 指定 Knowing / Applying / Reasoning 層次。

④ 驗證步驟 Verify

檢查產出的差異對照表，確認 A 版有解題支架，C 版有逆向推理。

🔍 放大黑板
問題 9

同步修訂只修改了單一檔案，漏掉聯動檔案

① 現象 Symptom

學生版學習單題目刪減了，但教師答案版仍然是舊版的題目與答案。

② 可能原因 Likely cause

修訂時未要求 Agent 先盤點關聯受影響檔案清單。

③ 修正動作 Action

發送指令：「請檢查教師答案版是否與學生版保持題號與內容一致，並提供 change-summary.md 說明修改。」

④ 驗證步驟 Verify

核對 output/03-revised/ 內的學生版與答案版題數與題目完全吻合。

🔍 放大黑板
問題 10

再次重用變成隨意複製貼上，丟失專案規則

① 現象 Symptom

輸入新課題時，Agent 忘記了繁體中文、中英文對齊或 output/ 目錄規範。

② 可能原因 Likely cause

新對話開啟了全域上下文重設，未引用 AGENTS.md。

③ 修正動作 Action

在同一個 OpenCode 專案工作區中執行 Prompt 7，並在開頭指名「保留 AGENTS.md 長期規則」。

④ 驗證步驟 Verify

新課題產出正確寫入 output/04-reused/，且完全遵守既有規則。

⚡ 30–40 人現場突發技術狀況 SOP（分級處置表）

針對學校 Wi-Fi、API 限流與初學者操作環境之突發情況處置：

故障現象 / 錯誤碼 性質判斷 講師決策與現場處置流程 主課是否暫停
1–3 人報錯 401 或安裝失敗 個人環境設定問題 1. 技術助手上前個別排查 API Key 是否填妥。
2. 若 3 分鐘內無法排除，請該學員先與鄰座老師併組共看。
3. 主課不停。 		不暫停
單一組別出現 429 限流 (Rate Limit) 瞬時連線過於密集 1. 該組學員全體停手 60 秒，不要連續按 Enter。
2. 其他組別維持原錯峰節奏（+15秒/+30秒）。
3. 60 秒後重新單獨送出。 		不暫停
超過 10 人同時出現 429 限流 主模型服務端負載超載 1. 全班全體停手 2 分鐘。
2. 講師統一宣布切換至備援模型（輸入 /models 選擇 Nemotron 3.5 Lightning Free）。
3. 各組以 30 秒為間隔重新錯峰發送。 		短暫停 2 分鐘
PowerShell 提示 npm.ps1 執行原則被阻擋 Windows 系統安全性原則 改用 Windows 內建之「命令提示字元 cmd」，避開 PowerShell 執行原則限制。 不暫停
全校 Wi-Fi 斷網或 API 提供商全域癱瘓 不可抗力基礎設施故障 1. 停止全體學員實操發送請求。
2. 切換為講師本機或預備好的已完成結果（Math-Agent-Workshop/backup/）進行大螢幕教學講解。
3. 維持教案主線推進，確保觀念與驗收標準傳達到位。 		轉為示範模式
